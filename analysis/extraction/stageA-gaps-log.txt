  python -I tools/ex_validate_batch.py --session <dispatch folder> [--session ...] --lookups <dir> --out <report>
      [--pass 1|2] [--append] [--first-pass <report>] [--output-file <jsonl>]      |  --self-test
  - Reads dispatch.json of each EA/EB session folder (EC refused: its output is not a first-pass record file),
    refuses a schema copy whose sha256 differs from dispatch.json, a missing dispatched text, unsafe ids.
  - Splits the output file (dispatch.json output_file, <EA|EB>-<batch>.jsonl) into records at "\n"; a line that is
    not a JSON object, an id not dispatched to that session, a second record with one id, and a dispatched id with
    no record are findings (check "session", severity fail) and are not validated (no text is opened for an
    undispatched id).
  - Validates each record in process with ex_validate.validate_record against fulltext/<id>.txt of that folder and
    the shared direction list (KA1(b) + <lookups>/metric-ids-v1.csv); writes ex_validate's finding lines and summary
    line (same fields; the summary gains metric_lookup_sha256; record_sha256 = sha256 of the record's line bytes).
  - Block checks (plan v0.2 s6.4 "blocks present match dispatch.json"), check "blocks": the record's blocks equal
    dispatch.json's blocks for that id (blocks_mismatch); no content in an undispatched block
    (content_outside_blocks; L: design, census, claims.CT, study fields other than main_comparison; Q: qa,
    claims.list, study.main_comparison; H: units_h; K: groups, units_k; the mapping is read from the brief's block

    not say so).

    basename). agreement.py already ignores lines with pass > 1, so G1 counts first pass only. --pass 1 refuses an
    (id, extractor) that already has pass-1 lines in the file it appends to; --pass 2 needs a first-pass summary for
    each validated (id, extractor) (--first-pass, or --out with --append) and refuses a second pass 2 (one return
    only). Without --append an existing --out is refused. Nothing is written on a refusal. Exit 0 / 1 (any fail) / 2.

OPEN QUESTIONS (written here, not implemented)
  Q1 G1 decision: do value-level failures reject the cited entry? Today agreement fails an entry (prose E.., table
     T.., cell C..) only when a fail line names it (table, cell, row, prose checks). Value-level fails name the unit
     or unit.arm (value_mismatch, value_outside_cells, value_not_in_quote, column_mismatch, where_mismatch,
     label_row_mismatch, condition/metric mismatches), sign fails name the unit (arrow_conflict,
     sign_conflict_in_group), and the new batch fails name a field or the record (blocks_mismatch,
     content_outside_blocks, block_content_missing, extractor_mismatch, session findings); none of them lowers
     G1a/G1b. Options: (a) keep (G1 = evidence located; value errors are measured by M-val and the sign by
     M-sign); (b) a value or sign fail also fails every entry its unit cites; (c) report G1 both ways and gate on
     one. Also open: whether a record rejected only for blocks or session findings counts as accepted at first
     pass. Needs a decision row before the gate.
  Q2 E1 coverage rule (brief v0.5 E1; v0.2 s6.4) is not precise enough to implement: (i) there is no
     machine-readable list of [Q] fields and their record paths (the marks are in prose, with variants "[Q per
     category; searched for none]", "[Q if yes ...; searched if no]", "[Q for any letter or U; searched for NS]");
     (ii) "positive value" is undefined for enum values such as other, NA, numbers and lists; (iii) the brief's
     negative list (no, not_stated, NS, "not stated", none) omits "unclear", which the schema's searched
     description includes; (iv) whether NA needs evidence or searched. Needs a field table (field id, record path,
     positive values, negative values) from method-architect; then it is a short check in ex_validate.
  Q3 Derived fields (--fill-derived): rules exist in pieces (value_num parser v0.2 s6.4; rq_class from factor_type
     U8 v0.3; U12 duplicates; metric_id and benchmark_id from the lookups; K15 matched as agreement's pool_flag;
     M14/M15 from the draw manifest), but under-specified: whether v0.2's QA scores (s7.1), QA3c, QA7n and D12
     levers (s4.3) still apply to the v0.5 item set; where filled records live (a new file, or the record file
     agreement reads, and before or after the pass-2 re-run); the unmapped-string queue format; whether a filled
