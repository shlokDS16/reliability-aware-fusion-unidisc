2. INTERFACE MISMATCHES FOUND AND FIXED (all in the consumer, analysis/extraction/agreement.py)
  I1 Row-level validator refs. ex_validate names row checks (row_start, row_width, row_complete) by the row's
     cell ids joined with "+" ("C04+C05"); Validator._hit matched only id, id+".", id+"[", id+":". A failed
     row therefore never failed its entries in G1. Fix: Validator splits each ref on "+" (fails and unverified).
  I2 column_unverified. agreement read check == "column_unverified" with ref = cell id (the synthetic shape of
     fixtures/synth.validator_lines); ex_validate emits check "column", status "column_unverified" (warn) or
     "column_mismatch" (fail), ref = the value (H unit id or "<K unit>.<arm>"). Every cell read as verified, so
     the U14 col pass ran on unverified cells and the column_unverified diagnostic was always 0. Fix: Validator
     also records check "column" lines with status column_unverified or column_mismatch by value ref, and
     verified(rid, ext, cell, vref) takes the value ref (h_info passes the H unit id, the K-value diagnostic
     passes unit.arm). column_mismatch is included because plan v0.5 s5.2 matches on col only for cells the
     validator marks column-verified (v0.3 s6.3 item 9), which a column_mismatch value is not. The old
     synthetic shape still works (existing tests unchanged).
  I3 --we file format. agreement's docstring names --we analysis/extraction/we-expected.jsonl but read it as
     one partial record per id ({"id","groups","units_k"}); build_we_expected.py writes one row per expected
     unit ({"record_id","kind","seq","group_id","where","second_factor","arms","anchor","benchmark","metric",
     "condition",...}). Result: InputError, Stage A could not run with --we. Fix: load_we folds unit rows into
     partial records (arms A1..An in list order; a markdown-string arms field, 38 of 267 K rows, becomes one
     arm; anchor_arm = the arm whose label equals anchor, else null, 36 rows; unit_id K<seq>); partial-record
     files load as before.
  I4 Null parts of worked-example keys. we-expected rows never give split and often give benchmark or
     condition as null; _we_record turned missing fields into "" and match_k compared them with the record's
     split ("test") and benchmark ("not stated"), so no K unit could ever match a worked example (F1_K 0 by
     construction). Fix: match_k_we treats a null worked-example key part (and split) as matching any value;
     with no null parts it equals match_k (first free equal key in reading order).
  The four fixes are listed in the output's spec_resolutions (I1-I4) and in the module docstring.
  Checked and consistent (no change): ex_validate summary line carries id and extractor (agreement's "seen"
  check); extractor strings EA-claude-opus-5-5 / EB-claude-sonnet-5-5 from dispatch.json match the schema
  pattern and the validator's echo; ex_dispatch --manifest accepts draw_pilot's stage-a keys (ids, stratum);
  draw_pilot's stage-a manifest keys are those agreement reads; ex_dispatch EC and agreement read the same
  lookup file names; route-severity lines are ignored by agreement, which recomputes the sign (R3).

      because ex_validate always adds its built-in KA1(b) list under the CSV while agreement uses the CSV only
      (a metric such as PPL missing from the CSV gets a direction in ex_validate and is routed to EC by
      agreement); (b) use only true / false / empty for higher_is_better (agreement also reads yes/no/1/0,
      ex_validate does not).
  [ ] E1 coverage rule for [Q]-coded fields and the searched rule (ex_validate log: not implemented; needs the
      field list).
  [ ] Self-test flags: plan v0.2 s6.5 gives ex_validate a --self-test; it has none (cases run from
      tests/test_ex_validate.py). ex_dispatch and draw_pilot have none either; agreement has one.
  [ ] Batch driver: ex_validate takes one record and one text per call; nothing splits a session file
      (<EA|EB>-<batch>.jsonl) into records, runs the validator with the dispatched text and concatenates the
      --out files into agreement's --validator input (the pipeline test does it by hand). Plan v0.2 s6.5 had
      --rows/--texts.
  [ ] Second-pass marking: agreement ignores lines with "pass" > 1, but ex_validate writes no pass field; a
      re-run after the one return to the session (plan s9) must be kept out of the first-pass file or tagged.
  [ ] Derived fields (--fill-derived: rq_class, value_num, K15 matched, metric_id, benchmark_id, duplicate
      flags): not implemented in ex_validate; plan v0.4 says records reach agreement already filled.
      agreement falls back on U8 and its own pool_flag, so Stage A runs, but the "stored id differs" diagnostic

  [ ] G1 definition: value-level fails (value_mismatch, column_mismatch, where_mismatch; ref = unit or
      unit.arm) do not fail the cited cell entry; only table, cell, row and prose checks do. Needs a decision

      pass@k; agreement's R3 reads arrows only in metric_printed and column_printed and keys metrics by
      norm_bm alone. Same unit can get different keys / arrow status in the two tools.
