## Findings and fixes

F1 (precondition, must be done): the driver refuses to launch while `exp_p2/` or `tools/` is dirty (`pins.require_clean`, `gate_driver.py:187-189`). Uncommitted: `exp_p2/gate/gate_driver.py`, `exp_p2/gate/build_f30k_fold.py`, `exp_p2/run_gate_lrf_f30k.py`; also uncommitted and needed for the record: `analysis/paper2/lrf/f30k_analysis.py`, `tests/exp_p2/test_lrf_f30k.py`. Commit these after the F2 to F4 edits, then launch from the clean tree. Do not use `--allow-dirty`.

F2 (medium, fix before launch): the analysis does not know the planned n. A run that stops with 800 to 871 items (guard abort not resumed, driver stop) would be reported with no "incomplete" marker because A7.6 only labels below 800. Fix in `f30k_analysis.py` near `:94-96`: read `n_rule.test_fold` from `runs/P2-LRF-PLAN-F30K/family.json` (or the fold length), add `n_planned`, `complete = (n == n_planned)` and, when not complete, put "partial prefix (n of n_planned)" in the F1, F-NI and F-LEN labels and set `headline_gain_claim_allowed` false. Add one test.

F3 (low, fix with F2): for a confirmed F1 with n < 800 the `wording` string (`:107-108`) is the full A7.5 sentence ("... raised accuracy ...") without the underpowered qualifier, although `label` carries it. Append the `under_label` to `wording` when underpowered (and the partial label from F2).

F4 (low, fix with F2): F-LEN silently drops rows that have no `y_lrf_L` / `y_none_L` (`have_L`, `:115`) without counting them; only length-mismatch exclusions are counted. Add `n_without_length_matched_scores = len(nz) - len(have_L)` to the F_LEN block (expected 0).

F5 (low, procedural): A7.3 requires "per-item arrays untracked with a SHA-256 manifest", but no code writes `arrays_manifest.json` (for L1 it has the form `{"n": 450, "files": {"item0000.npz": sha256, ...}}`, written outside the committed code; only `analysis/paper2/lrf/ablation.py:719` reads one). The lead must write it after the run (e.g. a short Written script, or add the command to the build report) and note it in the run report. Arrays are not ignored by git (`git check-ignore` empty), same as L1 (`?? runs/P2-LRF-L1/arrays/`); do not commit them.

F6 (info, no action needed): the condition index of `noise0.1` is 1 here and 2 in L1 (L1 also had jpeg10 before it). It only moves the jitter and arm streams of the GATE-M and size-matched arms (`arms.arm_rng(SEED_GATE, gid, ci, ...)`). Y_NONE and Y_LRF use `delta`, `deltaL` and the features B, D, q, s3, tbv, ltex, nbr (`lrf_score.raw_from_arrays`), none of which uses the flags, and the noise image uses `rung_rng(gid, "noise", 0)`, independent of `ci`. So F1, F-NI and F-LEN are unaffected; any GATE-M number from this run is not comparable to L1's and must not be reported as such.

F7 (info): `gate_driver.py` `STAGES["lrf-f30k"]` fallback n is 990 (stale; should be 872). Harmless: `default_n` reads 872 from the family file; the fallback only applies if the file is missing, and the runner would then refuse 990. Optional tidy.

F8 (lead's decision, not code): the fold file `runs/P2-LRF-F30K-FOLD/folds_f30k.json` (622 KB) contains the Flickr30K caption text of 872 images plus the wrong captions. A7.2 says the repository stores identifiers, never images; it does not say captions. The dataset card has no licence and the homepage states "non-commercial research" with a request form that was not used (build report, Data and licence). Decide before committing `runs/P2-LRF-F30K-FOLD/` (identifiers only, or captions with a stated basis). The builder cannot be rerun to change this (it refuses to overwrite).

F9 (info): the duplicate screen covers 950 COCO images only (build report concern 5). Three Flickr30K test images lie at 5 to 8 bits from a COCO image (minimum 6, confirmed by my independent hash); none is within the preregistered threshold, so none is excluded. No action under the plan.
